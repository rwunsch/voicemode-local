# A quieter Voice Pill with a visible speaker

The Voice Pill currently uses a small coloured dot to show who is speaking, while its surrounding controls stay on screen. Stephan approved an animated circular orb and a quieter layout on 18 November 2026. This change brings that design into the real Pill, so a person can recognise the speaker and reach Pause or Stop without keeping the whole panel visible during an answer.

## Approved design

The approved reference is the `felix-voice-pill-ui-enhancement.zip` shared with Robert on 18 November.

- FELIX: blue-violet above, magenta at the sides, orange below and a dark centre. Recreate this colour distribution; do not ship the sampled third-party screenshot from the prototype.
- The person speaking: the approved blue appearance.
- A sharp, circular edge, slow movement inside it and tiny independently rotating stars. A subtle outer bubble follows actual audio levels. No extra waveform.
- During an assistant answer, the surrounding Pill fades away. Hovering the orb or focusing it reveals the controls; they stay available while pointer or focus is in those controls.
- Pause and End remain distinct. Clicking the speaking orb requests the existing interrupt command; the runtime decides when listening actually resumes.
- Free mini orb, docked rail and tucked tab are supported alongside the existing menu-bar/system-tray form. Moving or minimizing changes presentation only, preserving voice state.
- Reduced motion, pause, missing audio levels and hidden windows have explicit static behaviour. Animation must not invent measured speech.

## Technical decisions

Keep the existing lightweight HTML, CSS and JavaScript page and the native macOS/Windows wrappers. Adding a UI framework is unnecessary for this rendering change and would add installation and packaging work. Keep the existing commands, voice/language selection, preview restrictions, machine-wide Pause and session-specific Stop.

The runtime remains the only source of speaker, recording, pause and stop state. Extend its existing control status with bounded numerical audio levels measured in the existing recording/playback paths. Do not open a second microphone, store audio or transcripts, or send levels over a new network port. The Pill receives them through its existing snapshots. Missing, stale, paused or disconnected measurements do not produce a speech-reactive bubble.

Use a small local WebGL renderer with its existing MIT shader attribution, a procedural colour asset and a static fallback. Cap frame rate and pixel density, release resources on context loss, and stop requesting frames when invisible or paused. Geometry and hit targets must work in the native non-activating windows, including macOS's forwarded pointer events.

## Alternatives considered

- Copying the browser prototype unchanged was rejected: its synthetic levels and simulated interrupt do not establish runtime behaviour, and its sampled screenshot is only a design reference.
- Replacing Pipecat/VoiceMode or changing queue and audio recovery behaviour is outside this change. Recent voice failures stay separate; an attractive UI is not evidence they are fixed.
- A second audio capture stream for the orb was rejected: it adds device contention and permissions while the runtime already owns the real streams.
- Removing visible controls entirely was rejected: keyboard and pointer users must still be able to Pause, Stop, select a voice and recover a minimized view.

## Validation and delivery limits

Check real state/command routing with the existing model and backend tests, new measured-level regressions against pristine voice-mode 8.12.0, and browser interaction tests using fake snapshots. Browser tests verify rendering and UI only. Native macOS checks cover geometry, hover, focus and interruption followed by continued listening in an isolated test profile. Native Windows acceptance must be reported separately if no Windows machine is available.

Run the full Python suite with `VM812_SRC` and `VOICEMODE_RELEASE_CHECK=1`, plus the Node model suite, on the final branch. Follow the Windows runner for changed Windows window code. Record actual results and any unavailable device check in the plan and PR. Do not merge, tag, change the installed FELIX or claim a release without the required separate decision.
